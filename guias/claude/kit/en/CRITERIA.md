# "Done" criteria

What each type of deliverable has to meet before it counts as done. If something doesn't meet it, it doesn't ship: it gets fixed or logged in `NONCONFORMITIES.md`. Each project's `CLAUDE.md` names this file in one line; it isn't copied.

| Type | It's done when… |
|---|---|
| **Signed text** | [It went through proofreading, it's in my voice and I approved it]. |
| **Code** | [Tests green, change with a description, version in the `CHANGELOG.md`]. |
| **Regulations and data** | Every data point has an official source with a link and a date, and a second pass checked it against that source. |
| **Work** | [Confidentiality reviewed, figures checked against the master source]. |
| **Scheduled task** | Its summary says what it did, and it didn't send, publish or delete anything outside what's allowed. |
| **Infrastructure change** (paths, skills, settings, tasks) | No broken paths remain and whatever uses it was tested. |
| [Other type] | [Verifiable criterion]. |
