Permisos que no abren la puertaPermissions that don't open the door

Qué le dejo hacer a Claude sin preguntar, y por qué un comodín cómodo puede ser un agujero.What I let Claude do without asking, and why a convenient wildcard can be a hole.

Claude Code pide permiso antes de correr un comando o abrir una página. A la vigésima vez que te pregunta si puede listar una carpeta, aprendés a aprobar por las dudas, y ahí está el riesgo. La solución es una lista de permisos en la configuración: lo que puede hacer solo, sin preguntar.

Armarla es fácil. Armarla bien me costó un error.

El comodín

Para no aprobar cada git log de cada repositorio, había dejado permitido git -C * log *: cualquier carpeta, cualquier opción. Parece inofensivo, porque git log solo lee. Pero git tiene opciones que ejecutan otros programas o escriben archivos, y el asterisco final las dejaba pasar todas. Un comodín sobre un comando con opciones peligrosas es una puerta con la llave puesta.

La regla nueva: no aprobar por comodín un comando cuyas opciones puedan ejecutar o escribir. Si lo uso seguido, lo escribo como un script fijo, que hace una sola cosa, y apruebo el script.

Lo demás que ajusté

  • Páginas web: Claude podía abrir cualquier sitio. Ahora tiene una lista de dominios. Lo que no está en la lista me lo pregunta.
  • Tareas que corren solas: la nocturna ya no tiene permiso para hacer push, publicar, mandar mails ni cambiar permisos. Deja borradores y yo decido.
  • Lo que Claude no puede tocar: su propia configuración. Cuando quiso sumar dos tareas de Windows y unos ganchos, el sistema lo frenó y me dejó los comandos para correrlos yo. Me dio trabajo, y está bien que me lo haya dado.

Para no aprobar a ciegas

Hay una skill, fewer-permission-prompts, que revisa tus transcripciones, encuentra los comandos de solo lectura que aprobás seguido y propone sumarlos a la lista. Sirve, con una condición: leé cada uno antes de aceptar. Ella propone; la llave la das vos.

El prompt

Revisá mi configuración de permisos de Claude Code y marcá cada regla que use comodines sobre comandos con opciones que puedan ejecutar programas o escribir archivos. Para cada una, explicá en una línea el riesgo y proponé una alternativa: una regla más estrecha o un script fijo que haga una sola cosa. Revisá también si puedo abrir páginas de cualquier dominio y qué permisos tienen mis tareas programadas. No cambies nada: mostrame la lista y la configuración propuesta como diff.

Claude Code asks for permission before running a command or opening a page. By the twentieth time it asks whether it can list a folder, you learn to approve just in case, and that's where the risk is. The fix is a permissions list in the settings: what it can do on its own, without asking.

Building it is easy. Building it well cost me a mistake.

The wildcard

To avoid approving every git log in every repository, I had allowed git -C * log *: any folder, any option. It looks harmless, because git log only reads. But git has options that run other programs or write files, and the trailing asterisk let all of them through. A wildcard on a command with dangerous options is a door with the key left in it.

The new rule: don't approve by wildcard a command whose options can run or write things. If I use it often, I write a fixed script that does one thing, and approve the script.

What else I adjusted

  • Web pages: Claude could open any site. Now it has a list of domains. Anything not on the list, it asks me about.
  • Tasks that run on their own: the nightly one no longer has permission to push, publish, send emails or change permissions. It leaves drafts and I decide.
  • What Claude can't touch: its own settings. When it wanted to add two Windows tasks and some hooks, the system stopped it and left me the commands to run myself. It gave me work, and it was right to.

Not approving blindly

There's a skill, fewer-permission-prompts, that goes through your transcripts, finds the read-only commands you approve often and proposes adding them to the list. It's useful, on one condition: read each one before accepting. It proposes; you hand over the key.

The prompt

Review my Claude Code permissions settings and flag every rule that uses wildcards on commands with options that can run programs or write files. For each one, explain the risk in one line and propose an alternative: a narrower rule or a fixed script that does one thing. Also check whether I can open pages on any domain and what permissions my scheduled tasks have. Don't change anything: show me the list and the proposed settings as a diff.
